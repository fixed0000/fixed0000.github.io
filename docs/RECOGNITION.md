# Kanji Recall: распознавание и ограничения

## Выбранный вариант

Локальное экспериментальное сопоставление формы штрихов с независимым корпусом KanjiVG (6 984 символа, включая кандзи и другие знаки). Это **не универсальная нейросеть распознавания почерка** и не сравнение только с ожидаемым ответом. Web Worker получает лишь массивы штрихов, без текста задания и правильного ответа. Отдельный модуль приложения сравнивает распознанную строку с допустимыми ответами.

1. Pointer Events дают последовательности нормированных координат в отдельном поле для каждого символа.
2. Каждый штрих передискретизируется в 16 точек по длине.
3. Весь символ масштабируется с сохранением пропорций.
4. Проверяются все образцы с тем же количеством штрихов. Минимальная стоимость назначения штрихов вычисляется алгоритмом Венгера. Направление штриха может быть обратным, порядок ввода не оценивается.
5. Среднее расстояние должно быть меньше 0.105, отрыв от второго кандидата — больше 0.012. Это инженерные пороги на ограниченном тестовом наборе, **не вероятность и не доказанная статистическая уверенность**.
6. Иначе возвращается неопределённый результат с кандидатами. Похожие символы не засчитываются автоматически: распознанная строка должна точно совпасть с одним из допустимых ответов.

Данные KanjiVG не являются корпусом реального почерка. Точное число отдельных штрихов существенно для метода; слитные штрихи, скоропись, нестандартные начертания, незаконченный рисунок и сложные кандзи могут приводить как к отказам, так и к ложным распознаваниям. Автоматическая проверка работает на тестовых случаях, но качество на произвольном человеческом почерке **не установлено**. Приложение сохраняет статус In Development.

Данные упакованы в base64 после округления координат SVG до целых единиц: около 3.6 MiB вместо 49 MiB исходной выборки точек. Подготовка и поиск выполняются в Worker. В браузере не используются внешние API, платные сервисы или регистрация; рисунки никуда не отправляются. Service Worker не установлен, холодный офлайн-запуск не обещается. Без доступных данных распознавания остаётся клавиатурный режим. Прогресс хранится только на устройстве.

## Рассмотренные альтернативы

| Вариант | Оценка для этого сайта |
|---|---|
| Web Handwriting Recognition API | Нуждается в поддержке браузером и японской модели платформы; нельзя полагаться на него для iPhone/Safari и общего GitHub Pages сайта. Не выбран как обязательный путь. https://developer.chrome.com/docs/web-platform/handwriting-recognition |
| Google Input Tools / облачные handwriting API | Сетевой сервис, передача штрихов и зависимость от внешнего endpoint; не соответствует предпочтениям задачи. Не интегрирован. |
| Tesseract.js | Движок OCR изображений, не специализированный онлайн-распознаватель японских штрихов. Пригодность для этой задачи не подтверждена; не используется и не выдаётся за проверенное решение. https://github.com/naptha/tesseract.js |
| Zinnia + обученная японская модель | Подходящий класс онлайн-распознавания, но нативный C++ и необходимость отдельного WASM-порта, проверенной модели и проверки её лицензии. Рабочий браузерный порт и модель здесь не подготовлены. Возможное следующее улучшение. https://taku910.github.io/zinnia/ |
| KanjiVG | Доступные открытые векторные штрихи, статическая доставка, прозрачная лицензия. Реализован ограниченный fallback без представления его как универсального распознавателя. |

Альтернативы рассмотрены по архитектуре и доступности; сравнительный benchmark обученных моделей не проводился. Это ограничение выполненной работы, а не утверждение, что качественная бесплатная модель невозможна.

## Что ещё необходимо

Проверить независимый корпус реального почерка, в том числе сложные символы всех 15 слов, на физическом iPhone и стилусе. Для более качественного распознавания — лицензированный японский handwriting dataset и WASM/ONNX-модель с измерением ошибок и калибровкой неопределённости. До этого нельзя заявлять о качественном универсальном распознавании или проверке 書き順.
