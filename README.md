# Lidiia Borodina — Portfolio

Статический сайт для GitHub Pages, японский по умолчанию, английский — в `/en/`. Рабочая ветка обновления: `portfolio-refresh`. Изменения не опубликованы.

## Локальный запуск

Python 3, без установки библиотек и без сборки:

```sh
cd /workspace/portfolio
python3 -m http.server 8000
```

Открыть http://localhost:8000/ или http://localhost:8000/projects/kanji-recall/ . Не открывать через `file://`: приложению нужны fetch и module Worker.

Альтернатива с Go: `go run go-server/server.go -d . -p 8000`.

## Архитектура

- 20 самостоятельных HTML-страниц, по 10 на язык; исходные 6 разделов сохранены.
- `portfolio.css` — общий дизайн и адаптивность; JS требуется только для Kanji Recall.
- `tools/build-site.py` — необязательный генератор оболочки и контента, не frontend framework. `tools/app-ja.html`, `tools/app-en.html` — исходные блоки приложения. После изменения генератора: `python3 tools/build-site.py`. Сгенерированные HTML уже находятся в репозитории, production-сборка не нужна.
- Experience/Education пока сохраняют свои блоки из существующих HTML. Их факты правятся непосредственно в этих четырёх HTML; повторная генерация сохраняет блоки.
- `js/kanji/app.js` — занятия, проверка, локальный прогресс, лёгкие достижения; `canvas.js` — Pointer Events / DPR / undo; `worker.js` — загрузка и распознавание в отдельном потоке; `recognizer.js` — экспериментальный поиск похожих штрихов независимо от ответа.
- `assets/kanji/words.json` — 15 заданий N5–N1, с ID, чтением, значениями ja/en, ответами, количеством символов и источником каждого слова.
- `assets/kanji/templates.json` — производные данные KanjiVG, лицензия CC BY-SA 3.0. Лицензии и attribution лежат рядом. Runtime-библиотеки не используются.
- Старые изображения, CSS, JS, Go server и PDF сохранены. Старые HTML-адреса продолжают перенаправляться; `?lang=en` теперь учитывается.

Локальные записи: ключ `kanji-recall-v1` в localStorage. Попытки, верные ответы, ошибки, отказы распознавания, пропуски, показ ответа, последнее повторение и трудные слова хранятся раздельно. Языковые версии используют один прогресс. Холодный запуск без сети не гарантируется.

## Проверки

Для браузерных проверок нужны Node.js, npm, Chromium и работающий сервер на порту 8000:

```sh
npm ci
npm test
```

Тесты используют Linux Chromium `/usr/bin/chromium`; основной browser-тест поддерживает `CHROMIUM_PATH`. При другой ОС поменяйте путь и в `tests/app-flows.cjs`. Playwright 1.56.1 и @axe-core/playwright 4.11.0 используются только для разработки, не загружаются сайтом.

Результаты и изображения: `artifacts/`. Отчёт: [docs/TESTING.md](docs/TESTING.md). Ограничения распознавания: [docs/RECOGNITION.md](docs/RECOGNITION.md). Исходный аудит: [docs/BASELINE.md](docs/BASELINE.md). Подтверждения владельца: [docs/CONFIRMATION.md](docs/CONFIRMATION.md).

## Повторная подготовка KanjiVG

Обычный запуск сайта этого не требует. Для изменения данных клонируйте https://github.com/KanjiVG/kanjivg отдельно и запустите:

```sh
node tools/build-templates.cjs /path/to/kanjivg
```

Обновите NOTICE с SHA источника, сохраните CC BY-SA 3.0 и повторите тесты. Текущая техника — ограниченное сопоставление формы, не универсальная нейросеть и не проверка порядка черт.

## Публикация

Корневая архитектура рассчитана на `fixed0000.github.io`, не на подпапку проекта. На Pages обслуживаются готовые каталоги с index.html, `.nojekyll` сохранён. Не требуется backend, сборщик или SPA rewrite.

Перед публикацией владелец должен проверить diff, факты и ограничения, затем явно разрешить push/merge в ветку, используемую GitHub Pages. Никакой push, deploy или изменение настроек Pages в рамках реализации не выполнялись.
